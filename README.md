# כובי · יועץ הרכב של שטראוס

בוט בעברית שעונה לעובד על השאלה **"מה יקרה לנטו שלי?"** כשהוא מחליף רכב חברה, עובר לחשמלי, נכנס למסלול ברוכת ילדים או מוותר על הרכב.
עם כובי התשובה מגיעה בתוך דקה, עם השוואה ברורה והסבר.

**אתר חי:** https://strauss-car-advisor-y1x6.onrender.com (עובד) · https://strauss-car-advisor-y1x6.onrender.com/rep (נציג התחבורה)
קודי הכניסה והסיסמה נמסרים בנפרד, ולא נשמרים בגיט. השרת החינמי נרדם אחרי זמן בלי שימוש, ולכן התשובה הראשונה עשויה לקחת כחצי דקה.
**האתגר:** האקתון AI קוד פתוח 2026

> כל הנתונים בפרויקט פיקטיביים, חוץ מקודי הרכבים ושווי השימוש (המאגר של רשות המסים) ומפרט הרכבים (משרד התחבורה ו-EEA). אין להזין לבוט נתוני שכר אמיתיים.

## מה המערכת עושה

**מסך עובד**
- שיחה שאוספת רק את מה שחסר: שכר ורכיביו, הפרשות, נקודות זיכוי, עיסוק והרכב הנוכחי. אפשר להקליד, לעדכן פרופיל או להעלות תלוש שכר (תמונה או PDF).
- קבוצת הזכאות נקבעת בקוד מתוך העיסוק, לפי גיליון "עיסוקים". העובד לא נשאל עליה, והמודל לא מנחש אותה.
- תצוגת השוואה לכל חלופה: הרכב (או ויתור), האם העובד זכאי ולמה, עלות ותקציב, השתתפות, שווי שימוש, החזר חשמל או אחזקה, נטו משוער, הפרש מול היום והסבר קצר.
- העובד יכול לתקן נתון, והחישוב רץ מחדש.

**מסך נציג**
- כשחסר נתון שאין לו מקור רשמי, כובי שולח שאלה לנציג התחבורה ולא מנחש.
- הנציג רואה את השאלות הפתוחות ועונה. השיחה של העובד ממשיכה מאותה נקודה ומתעדכנת אצלו מיד. המצב נשמר גם אחרי רענון.

**הכללים** (מתוך מסמך האתגר)
- תקציב לפי קבוצה. אפשר לבחור רכב רק מהקבוצה של העובד או מקבוצה נמוכה ממנה.
- מסלול ברוכת ילדים: על הפער מעל התקציב העובד משלם 50%.
- רכב חשמלי: החזר של 250 ₪ נטו, מגולם.
- ויתור על רכב: רק בעיסוקים שמאפשרים זאת, תמורת אחזקה שחייבת במס.
- תקציב שלא נוצל לא משולם בשכר.
- שווי שימוש: נשלף מהמאגר של רשות המסים לפי המפתח הרשמי, ולא לפי שם מסחרי בלבד.

**פיצ'ר מקורי: דירוג רכבים לפי נתונים רשמיים**
- "איזה רכב הכי בטיחותי, הכי חסכוני או הכי מרווח מבין אלה שמגיעים לי?"
- כובי מדרג רק רכבים שהעובד זכאי להם: 6 קריטריוני מיון ו-11 מסננים. הנתונים ממשרד התחבורה (data.gov.il) ומ-EEA האירופי, וכל נתון מוצג עם המקור שלו.
- שאלות סובייקטיביות, כמו "מה יותר נוח", כובי מתרגם לנתון מדיד אחרי שאלת הבהרה. מה שאי אפשר למדוד, הוא לא מנחש.

## איך זה בנוי

```
דפדפן (React + Vite)
   │  REST + SSE
   ▼
FastAPI  ──►  איג'נט LangGraph  ──►  Gemini (גיבוי: Groq / OpenRouter)
   │              │
   │              └─ כלים: שווי שימוש · זכאות · חישוב נטו · שאלה לנציג · מפרט ודירוג רכבים
   │
   ├─ מנוע חישוב בקוד (דטרמיניסטי)  ◄── קובץ כללים JSON + קובץ נתונים Excel
   └─ Neon Postgres: שיחות, מצב האיג'נט, פרופיל, תלושים, שאלות לנציג
```

**העיקרון:** המודל משוחח, הקוד מחשב. כל מספר בכרטיס ההשוואה מגיע ממנוע החישוב ולא מהמודל. אותם נתונים ואותם כללים נותנים תמיד אותה תוצאה.

שרטוטים מפורטים (השכבות, המסלול של שאלה, ומסלול הנציג): [docs/architecture.md](docs/architecture.md).

| שכבה | טכנולוגיה |
|---|---|
| ממשק | React 19 + Vite, CSS, נגישות לפי WCAG 2.1 AA |
| שרת | Python, FastAPI, SSE לעדכונים חיים |
| איג'נט | LangGraph, ‏Gemini Flash, ‏fallback ל-Groq ול-OpenRouter |
| נתונים | Neon Postgres |
| מעקב | LangSmith (אופציונלי, כבוי כברירת מחדל) |
| אירוח | Render (שרת + אתר סטטי) |
| אפליקציה (אב-טיפוס) | React Native + Expo (`phonefrontend/`) |

## הרצה מקומית

**דרישות:** Python 3.12, ‏Node.js 22.13 ומעלה (האתר לבד: 22.12), ומפתח Gemini API.

### 1. שרת
```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate   |   macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # ולמלא את הערכים (פירוט למטה)
uvicorn app.api.server:app --reload --port 8000
```
בדיקה: `http://localhost:8000/health` צריך להחזיר `{"status":"ok"}`.

### 2. אתר
```bash
cd frontend
npm install
# קובץ frontend/.env עם: VITE_API_URL=http://localhost:8000
npm run dev
```
העובד ב-`http://localhost:5173` (קוד מ-`EMPLOYEE_CODES`), והנציג ב-`http://localhost:5173/rep` (`REP_PASSCODE`).

### 3. אפליקציה (אופציונלי)
```bash
cd phonefrontend
npm install
# phonefrontend/.env עם EXPO_PUBLIC_API_URL=http://<כתובת המחשב ברשת>:8000
npx expo start
```
סורקים את הקוד ב-Expo Go. השרת צריך לרוץ עם `--host 0.0.0.0`.

### שיחה בקונסול (בלי ממשק)
```bash
cd backend
python -m app.agent.chat
```
כותבים בתור העובד. `/rep` מציג את השאלות הפתוחות לנציג, `/rep 1 participation=250` עונה על שאלה 1 (אפשר כמה `שדה=ערך`: `carGroup`, `companyCost`, `participation`), `/card` מציג את כרטיס ההשוואה האחרון, ו-`/exit` יוצא.

## משתני סביבה (שרת)

הרשימה המלאה, בלי ערכים, נמצאת ב-`backend/.env.example`.

| משתנה | חובה | מה זה |
|---|---|---|
| `GOOGLE_API_KEY` | כן (או מפתח של מודל גיבוי) | מפתח Gemini. בלי אף מפתח של מודל השרת לא עולה. ב-Render השם הוא `GEMINI_API_KEY`. אפשר מפתחות נוספים: `GOOGLE_API_KEY_2` עד `_9` |
| `GROQ_API_KEY`, `OPENROUTER_API_KEY` | לא | מודלי גיבוי |
| `GEMINI_MODEL`, `GROQ_MODEL`, `OPENROUTER_MODEL` | לא | שם המודל. ריק: ברירת המחדל שבקוד |
| `EMPLOYEE_CODES` | כן, למסך העובד | קודי כניסה: `מספר עובד:קוד`, מופרדים בפסיקים. ריק: מסך העובד סגור |
| `REP_PASSCODE` | כן, למסך הנציג | סיסמה משותפת לנציגים. ריק: מסך הנציג סגור |
| `DATABASE_URL` | לא | Postgres (Neon, כתובת pooler). ריק: הכול בזיכרון, ונמחק כשהשרת עולה מחדש |
| `JWT_SECRET` | כן בשרת חי | מחרוזת אקראית ארוכה. ריק: כל הכניסות נגמרות כשהשרת עולה מחדש |
| `FRONTEND_ORIGIN` | כן בשרת חי | כתובת האתר המדויקת (CORS). מחוץ ל-Render מותר גם `localhost:5173` |
| `LANGSMITH_TRACING`, `LANGSMITH_API_KEY`, `LANGSMITH_PROJECT` | לא | מעקב. להפעיל רק עם נתוני דמה |

**באתר** יש רק `VITE_API_URL` (כתובת השרת) ו-`VITE_SUPPORT_EMAIL` (המייל בכפתור "שיחה עם נציג"). אלה לא סודות. **אין לשים מפתחות במשתנים של האתר**, כי הם נכנסים לקוד שכל דפדפן מוריד.

## הגדרות: מחליפים נתונים, לא קוד

| קובץ | מה יש בו |
|---|---|
| `backend/data/strauss-rules.json` | תקציבים, קבוצות, מסלול משפחתי, חשמלי, ויתור, שיטת חישוב הנטו |
| `backend/data/strauss-data.xlsx` | קטלוג רכבים, עיסוקים, עובדים לדוגמה ונטו ייחוס |
| `backend/data/vehicle-values-2026.csv` | מאגר שווי השימוש של רשות המסים (77,988 רכבים, ‏windows-1255) |
| `backend/config/agent.json` | ספים, טווחים ומגבלות, וכל הטקסטים שהעובד רואה |
| `backend/config/column-map.json` | מיפוי שמות העמודות בקבצים |
| `backend/config/specs.json` | כיוון המיון של כל מדד (למשל: בטיחות, גבוה יותר עדיף) |
| `backend/config/car-sources.json` | קישורים ליבואנים, ומיפוי לנתוני EEA |

בפיילוט מחליפים את קבצי הנתונים בנתונים האמיתיים של שטראוס. שני חריגים בקוד: כמה משפטים בפרומפט (`backend/app/agent/prompt.py`) מתארים את כללי שטראוס במילים, וצריך לעדכן אותם כשהכללים משתנים. והערך `unusedBudget` בקובץ הכללים לא נקרא בקוד: תקציב שלא נוצל אף פעם לא משולם, גם אם הערך ישתנה.

## בדיקות ואיכות

מתיקיית השורש, עם ה-venv של השרת פעיל:
```bash
(cd backend && pytest)                 # 639 עוברות, 37 מדולגות (בדיקות Postgres, בלי DATABASE_URL)
(cd frontend && npm test)              # 351, כולל סריקת נגישות (axe)
(cd phonefrontend && npm test)         # 23
```
- **עם `DATABASE_URL`:** גם בדיקות ה-Postgres רצות מול המסד: 672 עוברות, 4 מדולגות.
- **אפליקציה:** בהרצה הראשונה, כשהמטמון של Jest ריק, בדיקה אחת חורגת מ-5 שניות ונכשלת. בהרצה השנייה כל ה-23 עוברות.

**נכונות:** ששת העובדים לדוגמה מהאקסל מחושבים ומושווים לגיליון "חישובים": נטו היום ובחלופה, הפרש, מס, ביטוח לאומי ובריאות, החזר חשמל וחלק משפחתי. 54 מתוך 54 הערכים זהים כפי שהם מוצגים, בעיגול לשקל.

**אבלואציות שיחה** (מול מודל אמיתי: צריך מפתח ב-`backend/.env`, ועולה כסף):
```bash
cd backend
python -m evals.run_off_topic main_flow     # סטים: off_topic, in_scope, recommend, recalc, main_flow
```
הריצה האחרונה (22.10.2026): ‏51 מתוך 52 תרחישים עברו. התוצאות נשמרות ב-`backend/evals/results/`.

## מה עובד, מה המגבלות, מה נדרש לפיילוט

פירוט מלא: [docs/summary.md](docs/summary.md).

**עובד**
- הזרימה המלאה: עובד, כלים, חישוב, נציג, ועדכון חי אצל העובד.
- ארבע החלופות: החלפת רכב, חשמלי, מסלול משפחתי וויתור.
- העלאת תלוש ופרופיל עובד.
- דירוג רכבים לפי נתונים רשמיים.
- נגישות: הצהרת נגישות, ו-Lighthouse (21/10/2026): 100 במסך הפתיחה, ובצ'אט 25 מתוך 25 בדיקות עברו.

**מגבלות ידועות**
- כל הנתונים פיקטיביים, כולל טבלת העיסוקים והקטלוג. רק שווי השימוש, קודי הרכבים ומפרט הרכבים אמיתיים.
- הכניסה היא בקוד, ולא דרך חשבון ארגוני.
- המספרים בכרטיס מחושבים בקוד. הטקסט החופשי של המודל נבדק באבלואציות, אבל לא נאכף בזמן ריצה.
- נתוני EEA לשנה האחרונה הם נתונים ראשוניים (מסומנים כך). לסנטה פה אין מפרט במאגר של משרד התחבורה.
- האפליקציה לטלפון היא אב-טיפוס חלקי. הפערים מתועדים ב-`docs/phone-app-gaps.md`.
- הנגישות נבדקה אוטומטית וידנית, אבל לא אושרה על ידי יועץ נגישות מורשה. בדיקה אוטומטית מוצאת רק חלק מהבעיות, וקורא מסך אמיתי לא נבדק בכל המכשירים.
- לכל שאלה תקרה של 60 שניות, ואחריה "כובי עמוס". גם למודל אחד יש 60 שניות, ולכן מודל ראשון שלא עונה בכלל לוקח את כל הדקה, ולא נשאר זמן למודל הגיבוי.

**נדרש לפיילוט**
1. קבצי הנתונים האמיתיים של שטראוס: כללים, קטלוג ועיסוקים.
2. כניסה דרך החשבון הארגוני (SSO) במקום קוד.
3. מפתח מודל בתשלום, בתנאים שלא מאמנים על המידע, והסכם עיבוד נתונים לתלושים.
4. צוות נציגים מוגדר, וכתובת תמיכה אמיתית (כרגע placeholder).
5. רכז/ת נגישות, ובדיקה של יועץ מורשה.
6. ניטור בזמן אמת, והחלטה על מעקב שיחות (LangSmith) לפי מדיניות הפרטיות.
